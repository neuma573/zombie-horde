# 동적 카메라 추적

## 상태

- 최신 카메라 줌 구현 이후의 후속 연출 작업
- 플레이어 이동 및 전투 판정은 변경하지 않음
- 순수 추적 계산과 Phaser 카메라 적용을 분리함

## 목적

- 플레이어에게 고정된 현재 카메라를 약간 늦게 따라오는 방송 카메라형 추적으로 바꾼다.
- 실제 이동 방향 앞쪽을 조금 더 보여 주되 방향 전환과 정지 시 부드럽게 구도를 바꾼다.
- PC 휠 및 모바일 핀치 줌, 반응형 viewport, 월드 경계와 함께 동작한다.
- 게임 시작과 Scene 재시작에서는 이전 카메라 상태를 남기지 않고 플레이어에게 즉시 맞춘다.

## 현재 구현 분석

- `GameScene.updateCameraPosition()`은 매 렌더 update 후 `cameraScrollForPlayer()`에 Player 위치를
  직접 전달하므로 Player가 이동한 만큼 카메라도 즉시 이동한다.
- Phaser `startFollow()`는 사용하지 않는다. `GameScene`이 줌 변경, resize 및 Player 이동 후
  카메라 scroll을 직접 설정한다.
- `logic/camera.ts`는 줌을 고려한 scroll 제한, world view 및 world-to-screen 변환을 담당한다.
- `logic/cameraZoom.ts`는 휠·핀치의 공통 `targetZoom`, 프레임 독립적인 줌 보간과 해상도별
  최소 줌을 담당한다.
- `GameScene`의 월드 카메라와 UI 카메라는 분리되어 HUD와 모바일 control은 월드 줌의 영향을
  받지 않는다.
- Player 이동과 충돌은 기존 60Hz 고정 시뮬레이션 단계에서 확정된다. 카메라가 사용할 실제
  이동량은 장애물 및 월드 경계 적용 후 Player 시작점과 이동 종료점의 차이로 구한다.
  좀비와의 분리 보정은 카메라 중심 위치에는 반영하지만 이동 선행 방향으로 해석하지 않는다.

## 지시문과 실제 구조의 차이

- Phaser `startFollow(player, lerp)`는 렌더 프레임마다 선형 보간되므로 현재 프로젝트의
  프레임 독립성 규칙과 맞지 않는다.
- 별도 Phaser 목표 GameObject나 범용 `CameraController`는 현재 한 Scene 구조에 비해 책임과
  수명 주기를 늘린다.
- 따라서 `logic/cameraFollow.ts`가 Phaser 비의존 추적 상태를 계산하고 `GameScene`은 결과를
  기존 `cameraScrollForPlayer()`에 전달하는 최소 구조를 사용한다.
- 지시문에서 데드존은 “검토” 항목이다. 첫 구현에는 명시적 데드존을 적용하지 않는다.
  지수 수렴, 이동 속도 임계값 및 snap epsilon이 미세 진동을 억제하며, 별도 데드존은 Player와
  조준점의 화면 상대 위치를 추가로 바꾸므로 실제 조작감 검증 후 독립 작업으로 다룬다.
- 조준 방향 오프셋도 구현하지 않는다. 모바일 자동 조준과 수동 조준 경계를 카메라 작업에
  섞지 않고 이동 방향 선행만 구현한다.

## 추적 상태와 설정

`config/cameraConfig.ts`에 다음 값을 둔다.

- `followSpeed: 8`: Player 및 목표 구도를 따라잡는 지수 응답 속도
- `lookAheadDistance: 32`: 최대 이동 선행 거리(월드 단위)
- `lookAheadSpeed: 10`: 방향 전환 및 정지 시 선행 오프셋의 지수 응답 속도
- `movementSpeedThreshold: 8`: 이보다 작은 실제 이동 속도는 선행 방향으로 사용하지 않음
- 최대 속도 기준은 중복 숫자가 아니라 현재 `PLAYER_CONFIG.speed`를 참조함
- `followSnapThreshold: 0.01`: 목표와 충분히 가까우면 정확한 값으로 고정

순수 상태는 다음 의미만 가진다.

```ts
interface CameraFollowState {
  targetPosition: Position;
  lookAheadOffset: Position;
}
```

줌 상태, 핀치 상태 및 입력 포인터 소유권은 이 구조에 넣지 않는다.

## 갱신 흐름

매 고정 시뮬레이션 단계에서 다음 순서로 처리한다.

1. 기존 이동 및 장애물 충돌로 Player의 최종 위치를 확정한다.
2. 단계 시작점과 종료점으로 실제 이동 속도를 계산한다.
3. 속도가 임계값 이상이면 정규화한 이동 방향과 최대 속도 대비 비율로 목표 선행 오프셋을
   계산한다.
4. 정지하거나 구조물에 막혀 실제 이동하지 않으면 목표 선행 오프셋을 `(0, 0)`으로 둔다.
5. 현재 선행 오프셋을 목표 오프셋으로 지수 보간한다.
6. `Player 위치 + 보간된 선행 오프셋`을 원하는 카메라 구도로 삼는다.
7. 카메라 목표 위치를 원하는 구도로 지수 보간한다.
8. 렌더 update에서는 최종 목표 위치를 기존 줌·월드 경계 scroll 계산에 전달한다.

지수 계수는 다음 식을 사용한다.

```text
1 - exp(-responseSpeed × deltaMs / 1000)
```

생산 코드에서는 기존 `SIMULATION_CONFIG.fixedStepMs` 단위로 갱신하므로 같은 경과 시간과
같은 Player 이동 결과는 렌더 FPS와 무관하게 같은 카메라 상태를 만든다.

## 줌과 월드 경계

- 카메라 추적 상태는 월드 좌표로만 보관하고 줌 값과 분리한다.
- 줌 변경은 `targetPosition`이나 `lookAheadOffset`을 초기화하지 않는다.
- 현재 줌은 기존 `cameraScrollForPlayer(targetPosition, world, viewport, zoom)`에만 전달한다.
- 월드 가장자리에서는 기존 scroll clamp가 최종 렌더 영역을 제한한다.
- 경계 밖을 향하는 선행 목표가 계속 존재해도 카메라 scroll은 경계에 고정되므로 외부 영역이
  노출되지 않는다.
- 자동 조준 viewport와 조명 좌표는 실제 카메라 scroll을 기준으로 계산한다. Player 중심 고정
  가정을 사용하지 않는다.

## 초기화와 재시작

- `GameScene.create()`에서 Player 생성 후 `snapCameraToPlayer()`를 호출한다.
- snap은 `targetPosition`을 Player 위치로, `lookAheadOffset`을 `(0, 0)`으로 설정하고 현재
  카메라 scroll도 즉시 갱신한다.
- 현재 재시작은 `scene.restart()`이므로 create 단계의 snap이 이전 위치를 제거한다.
- Player 순간 이동, 맵 전환 및 부활은 현재 구현되어 있지 않으므로 미래용 이벤트나 인터페이스를
  만들지 않는다. 해당 기능이 추가될 때 동일한 snap 경계를 호출한다.

## 데드존

- 초기 데드존 크기는 `0 × 0`, 즉 별도 데드존 미사용이다.
- 고정 단계 지수 수렴과 `followSnapThreshold`로 미세 진동을 제거한다.
- 실제 플레이에서 미세 이동이 여전히 거슬릴 때만 줌을 고려한 화면 픽셀 데드존을 별도 작업으로
  검토한다.

## 테스트

Phaser 비의존 순수 로직에서 다음을 검증한다.

- 초기 상태가 Player 위치와 일치하고 선행 오프셋이 0임
- 이동 시 카메라 목표가 즉시 Player 위치와 같아지지 않고 부드럽게 따라감
- 오른쪽·왼쪽 이동에 대응하는 선행 오프셋
- 방향 반전 시 목표가 순간 이동하지 않고 연속적으로 변경됨
- 정지 시 선행 오프셋과 목표 위치가 안정적으로 수렴함
- 임계값 미만 실제 속도에는 선행 오프셋이 생기지 않음
- 같은 고정 단계들을 한 렌더 프레임 또는 여러 렌더 프레임으로 묶어도 결과가 같음
- snap이 추적 위치와 선행 오프셋을 즉시 초기화함
- 줌별 기존 카메라 경계 및 화면 좌표 테스트 유지

전체 기존 테스트를 유지하고 `npm test`와 `npm run build`를 실행한다.

## 수동 검증

- PC에서 직선 이동, 정지, 180도 방향 전환
- 벽을 향해 계속 이동할 때 선행 오프셋이 0으로 복귀하는지
- 대각선 이동에서 축별 속도 차이나 흔들림이 없는지
- 0.75, 1.0, 1.5 줌에서 추적 지연의 체감이 과도하게 달라지지 않는지
- 맵 네 경계와 모서리에서 월드 밖 노출 및 카메라 떨림이 없는지
- 모바일 이동 스틱의 저속 입력과 최대 입력에서 선행 거리 차이가 자연스러운지
- Game Over 후 반복 재시작 시 카메라가 즉시 Player 위치에 맞는지

## 완료 조건

- Player 이동 시 카메라가 약간 늦게 따라오고 정지 후 안정적으로 수렴한다.
- 실제 이동 방향 앞쪽을 최대 32 월드 단위까지 더 보여 준다.
- 방향 전환과 정지에서 카메라가 순간적으로 튀거나 지속적으로 진동하지 않는다.
- 추적 상태는 60Hz 고정 단계에서 갱신되어 렌더 FPS와 분리된다.
- 줌 보간과 위치 추적 상태가 분리되어 있으며 줌 중 목표 위치가 초기화되지 않는다.
- 월드 경계 밖이 노출되지 않는다.
- 시작과 Scene 재시작에서 Player 위치로 즉시 snap한다.
- 조준 오프셋, 별도 데드존 및 미래 순간 이동 시스템을 선행 구현하지 않는다.
- 기존 이동, 조준, 사격, 충돌, 줌 테스트를 삭제하거나 완화하지 않는다.
- TypeScript, 전체 테스트 및 빌드가 통과한다.

## 제외 범위

- 조준 방향 카메라 오프셋
- 자동 조준 기반 카메라 이동
- 명시적 Phaser deadzone
- 카메라 흔들림, recoil, cinematic pan
- 컷신, 맵 전환, 순간 이동 및 부활 시스템
- 카메라 설정 UI
- 범용 Camera Manager 또는 여러 Scene용 프레임워크
