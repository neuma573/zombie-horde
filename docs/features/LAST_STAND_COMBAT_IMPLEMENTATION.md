# Hazard 야간 전투 1차 구현

`LAST_STAND_MODE_COMBAT.md`의 1차 범위(52~55절)를 구현한다. 동료 전투,
후반 도시의 실제 맵과 저장은 포함하지 않는다. 후속 요청에 따라 첫날 전투와 다음 Day 진행을 연결했다.

## 전투 연결

- 탐색에서 수리한 바리케이드 내구도와 무기고의 두 슬롯을 전투 시작 데이터로 전달한다.
  슬롯 1을 비우고 슬롯 2에 권총을 배정해도 그대로 시작한다.
- `LastStandCombatScene`은 `GameScene`의 기존 이동, 입력, 사격, 근접 공격,
  재장전, 시각 효과, 카메라 및 반응형 HUD를 공유한다.
- `LastStandCombat`은 Phaser 없이 구역별 내구도, 목표, 침입 여부, 승패를 관리한다.
  시간은 기존 `advanceGameTime`을 사용하며 23:00~05:00은 실시간 3분(일반 모드의 2배 속도)이다.
- 플레이어는 도시 설정의 `combatArea` 내부에 머문다. 좀비는 자기 구역의
  바리케이드를 공격하고, 붕괴 후 해당 `breachArea`를 거쳐 플레이어를 추적한다.
  `interiorArea`는 건물 전체 실내이고 `combatArea`는 바리케이드 뒤 플레이어 방어 구역이다.
  좀비는 외부에서 왼쪽 출입구(`entranceArea`)로 들어와 실내 접근 공간(`approachArea`)을
  통과한 다음 내부 바리케이드 앞에서 막힌다. 단순 건물 진입으로 패배하지 않는다.
  외벽·출입구·집기는 기존 경로 탐색과 충돌 판정이 사용하며, 실내 조명과 바닥은
  바리케이드 양쪽에 연속해서 이어진다.
  침입한 좀비와 접촉하면 체력과 무관하게 즉사한다.
- 바리케이드는 이동을 막지만 플레이어의 hitscan 사격은 통과시킨다.
  건물 벽은 이동과 사격을 모두 막는다.
- 예비 탄약만 무제한이다. 탄창, 사격 간격과 재장전 시간은 기존 무기 설정을 사용한다.
  탐색의 Ammo 자원은 소비하지 않는다.
- 승리하면 새벽 안내에서 다음 날 탐색으로 넘어가며 남은 바리케이드 상태를 넘겨준다. 패배하면 짧게 쓰러지는 연출 후 명시적인 확인 버튼으로 기존 무기고에 돌아간다.
  탐색 결과, 낮 내구도와 무기 배정은 유지하며 무기를 다시 배정해 방어를 시작할 수 있다.

## HUD와 실내 표현

- 라스트 스탠드의 체력바 자리를 바리케이드 내구도 게이지와 백분율 표시로 교체한다.
- Hazard 거점은 낡은 타일 바닥, 목재 바리케이드, 두꺼운 벽, 진열대, 계산대와 상자로 표현한다.
  집기는 설정 데이터에 있으며 이동과 사격을 막는다.
- 실내에는 고정 조명을 적용한다. 생성 지점은 배우보다 위에 그리는 불투명 어둠으로 가리고 입구 방향으로 부드럽게 밝아져 걸어오는 모습만 드러낸다. 손전등과 총구 불빛도 생성 지점을 노출시키지 않는다.
- Horde의 체력바, 시간 속도와 야외 조명은 기존대로 유지한다.

## 간헐 유입과 밸런스

후속 사용자 지시인 “계속 간헐적으로 오며 기본 총으로 실력 있게 막아도
상당 부분 바리케이드가 손상”되는 방향으로 `HAZARD_INFLOW_CONFIG`를 분리했다.

- 첫 유입: 1.5초 후
- 한 무리: 좀비 2~4마리, 무리 안에서는 0.7~1.3초 간격
- 무리 사이 소강: 7~11초
- 최대 동시 생존 좀비: 도시 전체 12마리
- 기존 좀비의 생존 여부와 관계없이 다음 무리가 계속 유입된다.
- 동시 수 제한에 걸린 생성은 건너뛰며, 나중에 몰아서 생성하지 않는다.
- 25% 확률로 빠른 좀비를 생성하며 개체별 2~3배 속도로 계속 달린다. 이 달리기 규칙은 Horde에도 공통 적용한다. 시간별 생성량 증가는 적용하지 않는다.
- 바리케이드 공격: 타격당 1%p, 기존 기본 좀비의 준비 시간 260ms와 공격 주기 800ms 사용.

`hazardDefenseBalance.test.ts`는 seed 17, 520 월드 단위 시야, 목표 전환 200ms,
초당 5발의 정확한 권총 사격, 즉시 재장전 조건으로 압박을 비교한다. 현재 기준에서는
빠른 좀비를 포함하여 49마리를 처치하고 05:00까지 생존하며 바리케이드가 100%에서 97%로 감소한다.
방어하지 않으면 새벽 전에 패배한다. 이동은 실제 게임과 동일하게 갱신 전 군집의
충돌 후보로 `resolveZombieCrowdSpacing`을 계산하고, 그 보정 속도를
`movePursuingZombie`에 전달한 뒤 장애물 충돌을 적용한다. 빠른 좀비의 속도도 이
공통 추적 함수에서 결정한다. 이는 조준 오차나 화면에서의 가시성을 포함한 실제
사람의 승률을 의미하지 않으며 실기 플레이에 따라 조정할 수 있다.

## 파일 책임

- `src/config/lastStandCombatConfig.ts`: Hazard 배치, 유입, 시간·공격 설정
- `src/types/lastStandCombat.ts`: 도시·구역·시작 데이터 계약
- `src/logic/defenseSector.ts`: 상태 경계, 영역 제한과 침입 구간 판정
- `src/systems/LastStandCombat.ts`: 구역별 방어 및 승패
- `src/systems/DefenseSpawnSystem.ts`: 사살 수와 독립적인 간헐 생성
- `src/effects/DefenseMapView.ts`: 거점·바리케이드 시각 표시

Horde는 기존 웨이브, 예비 탄약, 접촉 피해와 보급 규칙을 유지한다.

### 콘티 후속 조정: 작은 방어 공간과 전체 화면

- Hazard 플레이어 구역 폭을 520에서 220으로, 실내 폭을 1020에서 720으로 축소했다. 오른쪽 가구와 벽을 함께 옮겼다.
- 밤 전투의 시작/화면 회전 시 출입문과 실내 전체를 HUD와 모바일 조작부 사이에 맞춘다. 숨겨진 생성 공간은 기본 구도에서 제외한다. 휠/핀치로 확대·축소할 수 있고 확대 시 플레이어 쪽으로 구도를 이동한다.
- 바리케이드는 균일한 테두리 대신 서랍장, 상자, 낡은 의자와 못 박은 널빤지를 쌓은 형태다. 충돌과 파괴 판정은 기존 시스템을 사용한다.
- 사망 메시지는 현재 방어 일수를 넣은 “당신은 최선을 다했지만, {N} 일만에 마침내 당신은 사망했습니다.”이며 버튼은 “확인”이다. 확인 후 무기고 복귀를 유지한다.

### 밀치기와 스태미너 제거

- 라스트 스탠드에서는 밀치기 버튼·Space 입력·밀치기 판정을 비활성화한다. 숨겨진 버튼 자리는 조준 터치로 사용한다.
- 스태미너 표시·회복·근접 무기의 소모를 제거한다. Horde의 밀치기와 스태미너는 유지한다.
- 모든 모드의 빠른 좀비는 생성 시 정해지는 개체별 속도를 계속 유지한다. 달리기 대기/휴식/거리 전환 설정을 제거했다.

### 첫날 도입과 다음 날 진행

- 첫날 일기는 담백한 세 문단으로 쓴다. 밤 11시 도착, 바리케이드와 권총 준비, 새벽 5시까지 방어, 다음 날 물자 수색·수리·휴식 계획을 간단하게 전달한다. 조작키·퍼센트·일차 해금 같은 시스템 설명은 본문에서 제외한다. 페이지를 읽은 뒤 마지막 “전투 시작”으로 바로 전투에 진입한다.
- 첫날에는 탐색·수리 계획을 막으며 기본 권총을 슬롯 1에 자동 장착한다. 별도 무기고 단계는 없다. 첫날 패배 시 확인 후 무기고로 돌아가는 기존 동작은 유지한다.
- 새벽에 살아남으면 Day가 1 증가하고 12시간의 탐색/수리 계획을 새로 시작한다. 자원, 탐색 완료 장소, 무기 배정은 유지하고 바리케이드는 전투 종료 시 남은 비율을 사용한다.
- 같은 날의 승리 결과를 중복 처리해 Day가 여러 번 증가하지 않도록 검증한다.

### 빠른 좀비 회귀 테스트의 기준

사용자의 확정 요구사항은 “빠른 좀비로 선정된 좀비는 계속 달린다”이다. 이전의 근접 시 달리기, 1초 간격 발동, 달리기 종료 후 휴식은 폐기된 규칙이므로 다시 활성화하지 않는다.

- 기존 근접 조건 검증 → 가까운/먼 목표 및 옛 260 거리 경계 양쪽에서 즉시 달리고, 목표 거리가 바뀌어도 개체 속도가 유지되는지 검증한다.
- 기존 1초 발동 검증 → 999ms, 1000ms, 1001ms 전후에도 같은 달리기 속도를 유지하는지 검증한다.
- 기존 휴식 검증 → 실제 이동을 매번 갱신하며 60초 동안 속도가 떨어지지 않는지 검증한다.
- 기존 분할 시간 동등성 → 2400ms 단일 갱신, 800+1600ms, 144프레임 분할의 이동 거리가 같은지 검증한다.
- 같은 입력에서도 일반 좀비는 기본 걷기 속도이며 빠른 좀비는 목표를 지나치지 않는지 검증한다.

검증 대상은 GameScene의 두 게임 모드가 공통으로 사용하는 `movePursuingZombie`이다. 테스트 전용 이동 공식을 만들지 않고 기존 속도 선택·군집 이동 호출을 이 함수로 추출했으며, 충돌·넉백·길 찾기 규칙은 유지한다.
