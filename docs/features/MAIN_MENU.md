# 메인 메뉴와 캐릭터 선택

## 목적

- 게임 실행 직후 전투를 시작하지 않고 메인 메뉴를 표시한다.
- 화면 방향에 맞는 폐허 도시 배경과 게임 로고를 메인 메뉴에 표시한다.
- 메인 메뉴의 `SURVIVAL MODE` 액션으로 캐릭터 선택 흐름을 시작한다.
- 메인 메뉴 위에 표시되는 설정 모달에서 전역 음소거 상태만 변경한다.
- 게임 시작 전에 두 외형 클래스 중 정확히 하나를 선택한다.
- `src/assets/characters/male.webp`, `src/assets/characters/female.webp`를 선택 카드에
  표시한다.

## 화면 흐름

```text
메인 메뉴
  ├─ 설정 모달 → 음소거/소리 듣기 → 메인 메뉴
  └─ 게임 시작 → 클래스 선택 → GameScene
```

- 클래스가 선택되기 전에는 전투를 시작할 수 없다.
- 클래스 선택은 단일 선택이며 새 선택이 이전 선택을 대체한다.
- 뒤로 가기는 메인 메뉴로 돌아간다.

## 전역 상태

Phaser 게임 전역 Registry에 다음 상태를 저장한다.

- `settings.soundEnabled`: 기본값 `true`
- `session.characterClassId`: 선택한 클래스 ID

현재 게임에는 오디오가 없으므로 `soundEnabled`는 재생 동작을 일으키지 않는다.
향후 오디오 구현은 이 값을 읽어 음소거 정책에 적용한다.

## 클래스

- `male-survivor`
- `female-survivor`

두 클래스는 현재 능력치와 게임 판정이 같다. 선택 화면은 서로 다른 크로키 이미지의
전신에 가까운 crop을 사용한다. PC에서는 중앙의 큰 패널을 대각선으로 나눠 두 생존자를
한 장면에서 비교하고, 모바일에서는 같은 분할 구도를 세로 화면에 맞춰 압축한다.
하체를 포함한 전신 구도는 선택 전후에 유지한다. 선택한 영역은 `John Doe` 또는
`Jane Doe` 이름과 함께 전신 크기, 강조 색상 및 짧은 이동 효과를 키운다. 각 옵션은 `portraitTextureKey`,
`portraitUrl`, `portraitCrop`을 가지며 Vite가 런타임 캐릭터 이미지를 빌드 에셋으로
포함한다.
URL이 없는 향후 옵션은 임시 실루엣으로 대체할 수 있다.

## 반응형과 수명 주기

- 메뉴는 `Phaser.Scale.RESIZE`와 CSS safe-area 값을 사용한다.
- 가로 화면은 `mainmenu.webp`, 세로 화면은 `mainmenu-mobile.webp`를 선택하고,
  원본 비율을 유지한 `cover` 방식으로 빈 영역 없이 채운다.
- 회전 시 즉시 배경을 전환할 수 있도록 두 방향 이미지를 선로딩하되, WebP로
  압축해 초기 전송량과 texture 메모리 부담을 줄인다.
- 로고와 메뉴 액션은 safe area의 가용 폭과 높이를 기준으로 크기와 위치를 정한다.
- 게임 시작은 중앙의 주 액션으로, 설정은 우측 상단의 보조 아이콘으로 구분한다.
- UI 기본 팔레트는 남색 대신 따뜻한 차콜, 회갈색, 오프화이트와 저채도 적색을
  사용한다. 캐릭터 선택에서는 성별 구분을 위해 남성 파랑과 여성 분홍을 유지한다.
- resize 시 현재 화면과 선택·설정 상태를 유지하면서 UI만 다시 배치한다.
- 클래스 선택의 `BACK`과 `DEPLOY`는 사용 가능 폭이 좁으면 함께 축소하며 12px 간격을 유지한다.
- Scene shutdown에서 resize 리스너와 메뉴 객체를 정리한다.
- PC와 모바일 모두 포인터 입력으로 조작할 수 있다.
- 설정 모달이 열린 동안 뒤쪽 메인 메뉴 액션은 입력을 받지 않는다.
- 설정 모달은 배경이 비치는 반투명 패널과 스크림을 사용하고 열고 닫을 때 짧게
  페이드 인·아웃한다.

## 제외

- 실제 오디오와 배경음악
- 클래스별 능력치와 스킬
- 캐릭터 외형을 Player 렌더링에 적용하는 작업
- 저장소 또는 브라우저 영구 저장

## 검증

- 음소거 토글은 기존 설정 객체를 변경하지 않고 새 상태를 반환한다.
- 두 클래스만 선택 가능하다.
- 새 클래스 선택은 이전 선택을 대체한다.
- 잘못된 클래스 ID는 선택 상태를 변경하지 않는다.
- `npm test`와 `npm run build`가 통과한다.
