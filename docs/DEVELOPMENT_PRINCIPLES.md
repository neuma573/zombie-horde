# 개발 원칙

이 문서는 `docs/archive/MVP_DESIGN.md`에 기록된 설계 내용 중 이후 개발에도 지속해서 적용할 원칙만 분리해 정리한다.

## 1. 범위와 구조

- 현재 작업과 마일스톤에 필요한 기능만 구현한다.
- 미래 기능을 위한 확장 가능성은 열어 두되, 현재 범위에 필요하지 않은 객체, 시스템, 범용 추상화는 선행 구현하지 않는다.
- ECS, 서비스 로케이터, 이벤트 버스와 같은 범용 구조는 현재 규모에서 필요성이 확인될 때 도입한다.
- 공간 분할과 객체 풀 같은 최적화는 실제 성능 문제를 측정한 뒤 도입한다.
- 역할별 설정은 해당 설정 파일이 소유하며, 모든 설정을 모은 전역 객체에 런타임 시스템을 결합하지 않는다.

## 2. 의존성과 책임 분리

- Phaser Scene은 입력, 엔티티, 시스템, HUD와 효과의 수명주기를 연결하는 조정자 역할을 맡는다.
- 이동, 조준, 사격, 충돌, 피해, 웨이브와 세션 전환 같은 핵심 판정은 가능한 한 Phaser에 의존하지 않는 순수 로직으로 작성한다.
- 엔티티는 자신의 표현과 최소 상태를 소유하고, 이동·피해·상태 전환 계산을 직접 수행하지 않는다.
- 상태를 보관하는 시스템은 순수 로직을 호출하고 Phaser 객체와 도메인 상태 사이를 연결한다.
- HUD는 도메인 상태를 읽기 전용 화면 모델로 투영하며 게임 상태를 변경하지 않는다.

## 3. 게임 판정과 시각 효과

- 게임 판정을 먼저 완료한 뒤 그 결과를 사용해 시각 효과를 생성한다.
- tracer, 총구 섬광, 피격 효과와 사망 효과는 명중이나 피해 판정에 참여하지 않는다.
- 시각 효과 객체는 엔티티나 판정 대상 목록에 포함하지 않는다.
- 효과는 수명이 끝나거나 Scene이 종료될 때 정리한다.

## 4. 무기와 hitscan

- 기본 화기는 이동하는 Bullet 객체를 만들지 않는 hitscan 방식으로 판정한다.
- 실제 이동과 충돌이 필요한 특수 무기에만 Projectile 객체를 사용한다.
- hitscan은 발사 원점과 정규화된 조준 방향을 기준으로 판정한다.
- 명중 후보는 광선 진입 거리순으로 처리하고, 같은 거리에서는 결정적인 기준으로 순서를 정한다.
- 관통 수 제한은 한 발이 명중시킬 수 있는 전체 대상 수로 해석한다.
- 발사에 성공한 경우에만 탄약을 소비하고 hitscan 판정, 피해와 효과를 실행한다.

## 5. 시간과 프레임 독립성

- 모든 시간 기반 게임 로직은 Phaser가 제공하는 밀리초 단위 `deltaMs`를 사용한다.
- 이동 거리는 속도와 경과 시간의 곱으로 계산한다.
- 쿨다운, 재장전, 생성 간격과 접촉 공격 시간은 경과한 delta만큼 갱신한다.
- 한 프레임이 여러 이벤트 간격을 지나더라도 발생해야 할 이벤트를 잃지 않도록 남은 시간을 소비한다.
- 이동 중 접촉은 최종 위치만 비교하지 않고 이동 전·후 구간을 사용해 판정한다.
- 음수 delta는 0으로 제한한다.
- 큰 delta에서도 시간과 이벤트 결과를 보존하되, 반복 계산 비용이 문제가 되면 별도로 측정하고 대응한다.

## 6. 상태와 수명주기

- 게임 상태 전환은 명시적이고 단방향으로 처리하며 동일한 전환 이벤트를 중복 발생시키지 않는다.
- Game Over와 같이 도메인이 정지한 상태에서는 허용된 입력과 UI 외의 게임 업데이트를 실행하지 않는다.
- 새 세션은 기존 상태를 부분 초기화하지 않고 상태 보유 객체를 새로 생성해 시작한다.
- resize는 플레이 영역과 표시 위치를 갱신하되 진행 중인 세션과 웨이브 상태를 초기화하지 않는다.
- Scene 종료 시 등록한 입력·resize 리스너와 생성한 UI·효과 객체를 정리한다.

## 7. 반응형 화면

- 플레이 영역과 UI를 특정 고정 종횡비에 종속시키지 않는다.
- 현재 viewport를 기준으로 이동 경계, 생성 영역, 카메라와 HUD 배치를 계산한다.
- 세로와 가로 화면 모두에서 핵심 플레이 영역과 UI가 잘리지 않도록 한다.
- HUD 배치는 좁은 화면과 넓은 화면을 구분하고 safe-area를 고려한다.

## 8. 결정성과 검증

- 동일한 입력과 delta에는 동일한 게임 판정 결과가 나오도록 한다.
- 핵심 로직은 Phaser 렌더링 없이 자동 실행하고 테스트할 수 있어야 한다.
- delta 분할 여부, 큰 delta, 경계값과 동일 거리처럼 프레임 독립성과 결정성에 영향을 주는 조건을 테스트한다.
- 기존 테스트를 삭제하거나 완화하지 않는다.
- 변경 후 `npm test`와 `npm run build`를 실행한다.
- 자동 테스트가 다루지 않는 실제 브라우저, 모바일 방향 전환, safe-area와 장시간 실행은 별도 수동 검증 대상으로 명시한다.
